## Global Admin Tenant Management

Use the Tenants page to review tenant records and manage platform-controlled tenant administration.

### What to check

1. Tenant identity, slug, status, and seat limits.
2. Assigned tenant-admin users.
3. Every user attached to the tenant, including role, password-reset, and support actions.
4. Tenant-admin candidates for controlled access changes.

### Tenant lifecycle

1. Start from the tenant list; search and create controls stay at the top.
2. Open a tenant to review its read-only detail page before editing.
3. Use **Deactivate** when the tenant should be preserved but its users should no longer be able to sign in.
4. Use **Archive** when the tenant should be hidden from the active list but retained for reference.
5. Use **Restore** or **Reactivate** when the tenant should return to service.

### Tenant admin assignment

From the tenant detail page, assign or change the tenant admin deliberately. This controls who can manage that tenant’s users from inside the tenant workspace.

### Important guardrail

Global admins can manage tenants across the platform. Tenant admins remain scoped to their own tenant and should not see global tenant controls.
